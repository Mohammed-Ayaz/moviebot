# Decisions

One dated line per design decision, newest last. When a decision changes, update docs/SPEC.md first, then the code.

- 2026-10-20: Python 3.12, discord.py 2.7 and SQLite through aiosqlite. One Discord server only.
- 2026-10-20: Four layers (bot, services, repositories, TMDB client). Calls point down only.
- 2026-10-20: Slash commands and buttons only; no privileged intents.
- 2026-10-20: Hosting on Oracle Cloud's Always Free AMD micro VM, with Healthchecks.io and weekly backups to Discord.
- 2026-10-21: Verdicts (liked, mixed, disliked) replace the planned two-axis ratings.
- 2026-10-21: AI work happens by hand through /export and /import. The bot never calls an AI, and an import may only add films and write why_watch.
- 2026-10-21: The layer packages exist from M0, so CI measures service coverage from the start.
- 2026-10-21: aiohttp is a direct dependency because the TMDB client imports it.
- 2026-10-21: bot.py and __main__.py count as the bot layer, so they may import discord. config.py never does.
- 2026-10-21: setup_hook adds each cog with add_cog and passes its dependencies to the constructor, instead of loading cogs as extensions.
- 2026-10-21: The default help command is removed, so @MovieBot sync stays the only text command.
- 2026-10-21: Settings read .env without changing os.environ. Real environment variables win over the file, and a blank value counts as not set.
- 2026-10-21: One shared aiosqlite connection. Writes go through Database.transaction(), which holds an asyncio lock, so two commands can't mix their writes into one transaction.
- 2026-10-21: The migration runner is the only code that builds SQL text. It wraps each file in BEGIN and COMMIT and sets PRAGMA user_version from the file's number, because PRAGMA can't take ? placeholders. Both come from the repo, never from users.
- 2026-10-21: migrations/ stays at the repo root, as in the spec. database.py finds it relative to the source tree, which works because the bot always runs from a checkout.
- 2026-10-21: Categories get their own small repository, db/categories.py, because /add and /list need them before the seed import exists.
- 2026-10-21: Services raise DomainError subclasses with plain-text messages. ui/errors.py turns those, and cooldowns, into private replies for commands and buttons alike, so cogs need no try/except.
- 2026-10-21: /add takes an optional year. From M3 it covers titles that aren't picked from TMDB.
- 2026-10-21: TMDB suggestions carry "tmdb:<id>" as their value. Anything else in /add's title is a typed title.
- 2026-10-21: A typed title is searched on TMDB once. Exactly one result with the same title, ignoring case and punctuation and within a year of any year given, is used as if picked; otherwise the film is saved as typed.
- 2026-10-21: /add defers privately, confirms privately, then posts the card publicly as a second message, so errors after the defer stay private.
- 2026-10-21: TMDB suggestions give up after 1.8 seconds, inside Discord's 3-second limit, and show nothing rather than an error.
- 2026-10-21: The TMDB client gives up instead of waiting when Retry-After asks for more than 5 seconds.
- 2026-10-21: The TMDB logo ships inside the package, in src/moviebot/assets/, and /about attaches it as a small thumbnail.
- 2026-10-21: Test doubles live in tests/fakes.py, and conftest.py hands them to tests as fixtures.
- 2026-10-25: Another's custom_id carries the /suggest filters (mb:another:<film_id>:<category>:<genre>:<side>), so Another keeps them.
- 2026-10-25: For the side filter, a film's side is its own or else its category's, and side "both" counts for either.
- 2026-10-25: When the last-10 rule leaves nothing, Another still leaves out the film on the card, unless it's the only one.
- 2026-10-25: The persistent buttons catch their own errors and reply through ui/errors.py, because discord.py only logs errors from DynamicItems.
- 2026-10-25: /list's expiring view holds a plain button with the Suggest custom_id. In discord.py 2.7, a DynamicItem inside an expiring view is unregistered for every message when that view stops.
- 2026-10-25: "We're watching this" marks the film watched and its suggestion chosen in one transaction, in SuggestionRepository.choose.
- 2026-10-25: The Suggest and Another buttons share a per-person cooldown of one click every 3 seconds, like /suggest.
- 2026-10-25: Anyone in the server can remove, edit, mark watched and unwatch any film, because the bot serves one friends' server. /remove still asks to confirm and posts publicly who removed what. /export and /import stay admin-only.
- 2026-10-25: The film options of /remove, /edit, /watched and /unwatch suggest films from the list with the value "film:<id>". A name typed without picking must match exactly one title, so the bot never guesses which film was meant.
- 2026-10-25: Searching the list for those options happens in Python, ignoring case and punctuation, because the list is small.
- 2026-10-25: /edit takes the category as an option, with the same suggestions as /add and /list, and the note in the pop-up form.
- 2026-10-25: Confirm and Cancel expire after 10 minutes and the /edit pop-up after 15, so questions nobody answers don't linger. If someone else removed the film first, Confirm says so.
- 2026-10-25: The seed import leaves out any film already on the list, by slug, TMDB id, or title and year, so films members added and their edits always win over the seed.
- 2026-10-25: --match-tmdb searches by title and year, then by title alone, because TMDB's year can be one off. It takes TMDB's id, poster and runtime, but keeps the seed's own title and year.
- 2026-10-25: The seed's blocklist entries go in with WHERE NOT EXISTS rather than ON CONFLICT, because the UNIQUE (title, year) constraint lets two NULL years through.
- 2026-10-25: The do-not-watch check matches titles ignoring punctuation as well as case, and a film or entry without a year matches on the title alone.
- 2026-10-25: Film cards show why_watch from M6 rather than M8, so the 196 imported films show their notes straight away.
- 2026-10-25: /export uses the spec's Appendix format, AI instructions included, from M6 on, so M8 only adds /import. Members appear by display name, each fetched once without the Server Members intent; someone who left is "a former member".
- 2026-10-25: The weekly backup is a daily check against a backups table (migration 0002). A backup is due 7 calendar days after the last one posted, so restarts never skip or repeat one, and the first goes out right after the first start.
- 2026-10-25: The backup copies the database with SQLite's backup API while holding the write lock, switches the copy out of WAL mode so one file holds everything, and posts it from memory. It's only recorded once Discord accepts it.
- 2026-10-25: BACKUP_CHANNEL_ID stays optional. Without it the bot runs, and logs that weekly backups are off.
- 2026-10-25: The TMDB refresh runs daily instead of monthly: up to 50 films whose details are over 150 days old, oldest first. It refreshes poster and runtime only, and stops for the day after 3 failures.
- 2026-10-25: /remove's and /add's Confirm and Cancel share a Question view: only the person who asked can answer, and the buttons go after 10 minutes.
- 2026-10-26: BACKUP_CHANNEL_ID and ADMIN_ROLE_ID can't be the server's own ID, the usual copy-paste mistake. As ADMIN_ROLE_ID it would make everyone an admin, because the @everyone role shares the server's ID.
